## Repeated-UI-rework root causes (durable, evidence: `docs/ui-fix-triage-report.md` + commit history)

## Text-fit measurement and localization landed (2026-09-02b, commit `55b6edf`)

- **The "long Chinese text will clip" premise was wrong and is now corrected by measurement.** Of the 152 shipped Keyed entries, only 6 render wider in Chinese than in English, each by one half-width unit (`US.Action.Eat/Joy/Undraft`, `US.Mood.Bad`, `US.Packs.Filter.All`, `US.Footer.SaveStatus.Saved`) — a CJK glyph costs one em while a Latin character averages half, so short Chinese words beat short English words in character count but not in pixels. Real clipping came from two other causes: hardcoded English prose, and text bands shorter than one line.
- Measurement seam: `ITextMetrics` now has `MeasureText` (wrapped height) **and** `MeasureWidth` (single-line width, Verse `Text.CalcSize` with wrapping off). Both live in one production implementation, `VerseFerriteTextMetrics`, which saves and restores `Text.Font`/`Anchor`/`WordWrap`.
- `UiFitAudit` (library) hooks the single text outlet `UiThemeDraw.Label`, is scoped per element by the layout pass (`BeginElement(entry.Path)`), deduplicates per element+text, caps itself at 48 findings, and does nothing until a host attaches and enables it. The settings window owns that lifetime through `UsTextFitAudit` (`Begin` on host creation, `End` in `PreClose`) and only when dev logging is effective.
- **Design constraint worth remembering: the audit's default axis must be height, not width.** Verse label drawing wraps text into the rect, so an ordinary paragraph's unwrapped width always exceeds its box; a width-first check flags every multi-line string as a defect while hiding the one that matters (wrapped lines that no longer fit the band). The width axis is opt-in through `singleLine` and is used only by surfaces that must stay one line: dropdown field label, dropdown trigger display, dropdown option rows, status badge.
- Defects that gate found and that are now fixed (do not reintroduce the constants): page-title caption had a fixed 18px band for prose up to 438px; the scope-tree inherited-scope hint sat in a 14px band and the preset selection summary in an 11px band, both below one Tiny line; the checklist allocated banner height **once** while Draw can render three banners, so the last one fell outside the card; `chrome/banner` and `state/empty` sized from constants. All now measure, and every one of them resolves its string through a single path shared by `Measure` and `Draw`.
- Localization is now a closed contract: the manifests carry `TitleKey` only (no literal `Title`/`Caption`/`Text`), the page heading, workspace nav, section titles, footer status, preset list, packs flow, model banners, distance presets and mode names all read Keyed entries, and both language tables hold 152 keys each with an identical key set. Machine tokens (binding names, persisted filter tokens like `EnabledOnly`/`ConflictOnly`/`OrphanOnly`, tab tokens, `SqueakActionScope.ToString()` values, element ids) were never translated; where one string served as both value and label they were split.
  - Gate 14 now enforces the localization contract (key parity, non-empty values, **identical `{n}` placeholder multisets between languages**, every referenced `US.*` key defined in both, no literal prose in manifests). Gate 15 drives the production host across 5 workspaces × 3 viewports for **both** language tables asserting zero overflow, includes an in-process positive control (a probe label that must be reported) so a silently disabled audit can never pass vacuously, and requires the audit to fire when one Keyed string is stretched past its column. **Read together with the 2026-09-03 section below: as written on 2026-09-02b the sweep's height half proved nothing.**
- Protocol: fmt=2 registry is now **10** events; the new one is `evt=ui.text.overflow` (DevOnly, warning) carrying `target=<element path> reason=<width|height> source=<tiny|small|medium> need=<px> have=<px>`. The overflowing text is deliberately not logged (labels embed third-party pack/Def names). The human sentence formats need/have to one decimal; the structured fields keep raw invariant-culture floats.
- Harness constraints learned the hard way: gate 14 scans `Source/UniversalSqueaker/UI/**` for **substrings** `UiText` / `UiPanel` / `Palette` / `SurfaceFrame` / `UiValueStore` / `UiInteract`, so no type under `UI/` may contain those tokens (the audit is `UiFitAudit`, and the log facade is `SqueakLog.LabelOverflow`, for exactly this reason). net472 has no `string.Contains(string, StringComparison)` at runtime even though the reference assembly advertises it. Argumented `"Key".Translate(args)` binds to `Verse.TranslatorFormattedStringExtensions`, so the stub must carry that type name, not just a `Translate` on `Translator`.
- Packaging fact (verified 2026-09-02b): `AssemblyInformationalVersion` embeds the full commit SHA, so **every** commit — including documentation-only ones — changes `1.6/Assemblies/*.dll` bytes and the settings-page build identity, even though nothing shipped changed. Compared two packages by extracted member: identical sizes, only the `+<sha>` string differs. Consequence: never claim "no shipped-byte change" for a rebuilt package, and don't swap a maintainer's in-flight test build for a newer label.
- Still open, not folded into this commit: `UsHelpCatalog` remains English literals — measured **12 sections + 29 items = 41 entries, 71 distinct English strings** (a translation-tone decision for the maintainer); container-level auto-width was NOT implemented — `UiLayoutEngine.ResolveColumnWidths` still reads only static `Width=`/equal split, so `nav-column 192` and `help-scroll 232` stay fixed and "widen for Chinese" is today achieved by growing bands, not columns; mode/preset/filter Chinese wordings (原版/回退/混音/禁用, 保守/均衡/强烈/自定义, 全部/仅启用/冲突/孤立) are proposed translations awaiting maintainer review.

## Text bands and the vacuous height axis (2026-09-03, commits `eba5336` + `e75ec28`)

- **Gate 15's height axis had never worked.** Its harness `StubMetrics.MeasureText` returned a constant `16f` while the audit's height rule is `MeasureText(...) > rect.height`, so every band of 16px or more passed regardless of the string. The width axis was genuine, which is why the 152-key measurement above stands while the height half of "no text overflow" did not.
- A second, independent defect hid behind the first: `UsKernelSettingsHost.Create` hard-coded `VerseFerriteTextMetrics.Instance`, and outside the game that yields no usable height, so every *measured* band collapsed back to its `Math.Max` constant while the audit measured against a different model. Of the 13 findings the honest sweep first produced, 8 were that model mismatch and 5 were real. The host now takes an injected `ITextMetrics` and the sweep uses one instance on both sides.
- Durable harness rule: **layout and audit must share one metrics instance, and that instance must be wrap-aware.** A constant-height stub turns every height assertion into theatre, and a positive control on the width axis will not reveal it.
- Five real constant-band defects are now measured and must not revert: help-panel header (20px), race/xenotype row detail line (never measured; the xenotype row additionally measured the bare name while drawing `name (race)`), filter chip row (24px), preset header title (16px — shorter than one Small line), tuning mood label (16px).
- Dropdown popups now own the click over anything they cover and clamp into the Host viewport, flipping above the trigger when there is no room below. The pre-existing popup lane hit-tested by exact rect equality and so could not express two rects claiming one point — a test-shape lesson as much as a bug fix.
- Both new guards were mutation-checked: restoring the old title-only row formula fails the layer-growth step, deleting the yield guard fails the overlap lane.
- Still outside the harness's reach: the help header's real trigger is glyph advance, which exists only in game. It is fixed by construction (measured band) and verifiable only in game, via `usdiag evt=ui.text.overflow` with detailed logging on.

## Composite popup path closed (2026-09-04, US `170e172` + library `44b00c5`)

- The 2026-09-03 popup fix covered only the manifest `DropdownWidget`. Every US dropdown (Tuning scope rows, domain picker, filter bar) is the composite `UsKernelDraw.Dropdown`, whose hand-drawn popup never called `UiSession.SetPopupRect` and never clamped or flipped into the viewport: with no published rect the yield guard in `UiNative.DropdownButtonCore` could not fire, so a trigger under an open popup kept eating the option click — the maintainer's "selecting Auto opens the next row's dropdown". The 09-03 mutation check proved the guard, not the publication, which is why it stayed green while the composite path was broken.
- `FerriteLib.UiKit.Kernel.UiPopup` is now the single owner of popup geometry and input: `RectFor` (below / flip / pin / horizontal clamp / unpublished-viewport pass-through) and `DrawOptionList` (panel, single-line option rows, `SetPopupRect` publication, row hit-test, consume-close-callback). The manifest widget and the US composite both delegate to it; both private copies are deleted.
- Coverage split, deliberate: the library proves the yield guard and the rect rule **given** a published rect (`KernelPopupTests`, mutation-checked); the consumer proves publication through the real production host (`CompositeDropdownPublishesCoveringRect` in `UniversalSqueakerKernelHostTests`). Both directions mutation-checked: deleting `SetPopupRect` fails two library lanes; reverting the composite to a panel-only draw fails the US lane with "no Tuning scope dropdown published its popup rect".
- Refactor assessment recorded with the fix: the popup family was the only structural duplication left in the UI (two implementations of the same geometry/input rules), and extracting it removed the duplication and the defect class together. The remaining open UI items are maintainer decisions (Knife 3 behaviours, overlay kernel-only cut, help-catalogue tone, built-in content) or crash-lineage risks (IMGUI group-stack restore outside `finally`), not further duplication — **no broader refactor is warranted**; reopen only if a second geometry/input duplication appears.

- **Root cause, second half (2026-09-04c, library `9a197a2`)**: the in-game ptrace showed the covered trigger comparing a *group-space* event pointer (618.7,254.3) against the *window-space* popup rect (821,310.7,…). ## Filter misalignment: two caches, two clocks (2026-09-04d, US `87e3cd6`)

- The post-filter misalignment ("only a workspace switch heals it") was an invalidation-clock mismatch, not a layout bug: `UsKernelSettingsSource.BuildView` cached by `Time.frameCount` while the layout cache expires on the session `ContentRevision`. A filter write landing in a frame's popup pass bumps the revision, so that same frame re-arranges against the still-stale cached view, and the next frame's fresh view draws into the stale snapshot - content and geometry disagree until the next bump. The view cache now takes its clock from the Host session (`AttachRevisionSource` wired in `UsKernelSettingsHost.Create`); the frame clock remains only as the pre-Host fallback.
- Evidence chain worth remembering: the in-game ltrace proved filter-bar Measure/Draw parity (677/677, stack false/false), the three-viewport live-vs-fresh parity lane proved snapshot geometry agrees, and the maintainer's screenshot showed the actual symptom is content-level (race layer and xenotype layer frozen in different filter states) - geometry checks alone cannot see it. The defect class is invisible to the harness (stubs have no advancing frame clock; the mutation passes), which is why a source invariant pins the wiring (`UiSourceInvariantTests.VerifyViewCacheSharesLayoutClock`) and the final verdict is in-game.
- Durable rule: **any cache whose contents feed layout must expire on the layout cache's clock**, never a wall/Unity clock; two clocks = a guaranteed staleness window whose size is one bump, and only user-visible when the write happens mid-pass.
- **Filter labels (2026-09-04e, US `d23ad22`)**: race/xenotype/author dropdowns display the Def's own translated label (`ThingDef.LabelCap` / `XenotypeDef.LabelCap`), never a raw defName - US does not own translation keys for Defs it does not ship; third-party races arrive translated through their own mods. The composite `UsKernelDraw.Dropdown` carries (display, value) pairs, so the write stays the machine token. `VoicePackDomainView.RaceDisplay` makes the xenotype row's race context read like the race layer's title. Options bindings are typed `FilterOptionView` end to end.
