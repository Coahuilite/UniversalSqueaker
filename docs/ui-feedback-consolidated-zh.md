## 2. 潜在全局性风险分析

> 风险等级：高 = 影响多个功能块或整体可用性；中 = 影响单个大功能块但体验关键；低 = 局部/视觉优化。

### 🔴 高风险

#### G1. 行高/文本裁剪问题
- **现象**：Basic toggles 等两行内容字体下半截断；维护者反馈“普遍存在于整个模组设置”。
- **影响范围**：所有卡片、行、按钮、说明文本。
- **可能根因**：多处硬编码行高（如 26/28/30）未按 `Text.CalcHeight` 或 `ITextMetrics.MeasureText` 动态计算；多行文本被放进固定高度矩形。
- **建议**：建立统一的“文本测量 → 行高”基线；所有复合行/卡片在 Measure 阶段用真实文本高度计算；对现有 widget 做一次高度审计。

#### G2. 控件“通路不可用”
- **现象**：相机高度指示器、相机高度预设等看起来存在但无法操作；SR 迁移时期的“忘记包”按钮也无通路，红色提示无法消掉；维护者怀疑普遍存在。
- **影响范围**：所有自绘交互控件。
- **可能根因**：
  - 只注册了 `UiInteract.Button` 但没有绘制可见表面/文字（玩家以为不可用）。
  - 被后续绘制的不透明 surface 覆盖，导致“看不见也点不到”。
  - 滚动视图 / 交互帧坐标变换错误，命中测试失效。
- **建议**：建立“每个可交互控件必须绘制 + 可命中 + 有视觉反馈”的检查清单；对全部 US widget 做可用性扫描。

#### G3. 下拉弹层定位错误
- **现象**：下拉列表没有在下拉框下方展开；Tuning Editor 中会出现在左侧某个位置。
- **影响范围**：所有在滚动内容中使用的 `input/dropdown`。
- **可能根因**：deferred popup 在 `PopScrollView` 之后绘制/注册，导致内容坐标没有转换到页面坐标；弹层绘制与命中测试错位。
- **建议**：让 popup 捕获注册时的滚动变换，或把 popup 绘制/命中放在滚动变换仍然有效的阶段；补充“滚动视图内下拉定位”测试。

#### G4. 自绘选取按钮视觉与交互一致性
- **现象**：当前切换/选取按钮“很丑，甚至不如原版”；SR 的底部发光条 / 左侧高亮条传统未带回。
- **影响范围**：模式卡、Tuning layer、segment、筛选 chip 等所有“切换选取项”控件。
- **可能根因**：自定义皮肤（`UsSurface.DrawSegment` / `ModeCardRenderer`）与玩家熟悉的原版/ SR 视觉语言不一致，缺少清晰的选中/可点击 affordance。
- **建议**：在 UiKit 层新增“原版语言包装”的选择控件，统一替换自绘按钮；同时恢复 SR 的底部/左侧高亮条作为选中态。

### 🟡 中风险

#### M1. Tuning Layer 不常驻
- **影响**：Tuning Editor 是核心编辑区；滚动后玩家丢失当前层级上下文。
- **建议**：Tuning Editor 内 layer 分段做成 sticky header，或独立固定区域。

#### M2. Action Scope 分类与过滤缺失
- **影响**：玩家难以找到目标动作；Biotech 防御性动作（哭泣/咯咯笑）不应暴露。
- **建议**：按“自主行为 / 可操作行为”分组；在数据/UI 层过滤掉防御性动作。

#### M3. 帮助系统缺少分层
- **影响**：右侧帮助只有当前区块一条文本，缺少“功能区总览 + 单项高亮/独立帮助”。
- **建议**：调研 Camera+ 后设计分层帮助模型。

### 🟢 低风险（局部）

- 包管理 race/xenotype 联动筛选。
- 未列出 xenotype 黯淡显示。
- 作者筛选下拉。
- 衰减图可拖节点包边高亮。
- Tuning Editor 高度细节。

## 3. 建议处理顺序

0. **先执行系统性排查工序**（见 `docs/ui-fix-triage-plan-zh.md`），输出问题清单与回归测试。
1. **再修全局风险 G2（不可用控件）与 G3（下拉定位）**：它们直接破坏核心交互。
2. **再修 G1（文本裁剪）**：影响整个设置的可读性。
3. **统一视觉 G4**：恢复 SR/原版设计语言，作为后续按钮/卡片的基础。
4. **随后处理中风险 M1/M2/M3**。
5. **最后处理低风险局部优化**。
