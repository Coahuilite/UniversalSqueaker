## 详细需求

### R3 — 帮助系统

- 以 Camera+ 的右侧固定帮助面板为准。
- 玩家不需要点击帮助按钮，也不需要悬停到帮助按钮上。
- 帮助信息固定、可扫读、不破坏布局。
- 窄屏无右侧面板时，再考虑降级方案（如折叠内联帮助）。

### R4 / R5 / R6 — 功能块布局与导航

- 三个功能块应是三个独立、连续滚动的设置区域，而不是机械拼在同一个长滚动页。
- 每个功能块有标题，标题作为左侧导航的锚点。
- 包过滤器属于包管理块，放在包管理块内部一起滚动。
- 左侧导航切换功能块时，只显示该块的连续内容。

### R7 / R8 / R9 — Tuning Editor 交互

- Domain 多选场景使用下拉菜单。
- Action Scope 使用下拉菜单列出玩家可选项。
- Mood 因子控件做成复合控件：滑条 + 数值输入 + `−/+` 微调按钮。
- 微调按钮要有清晰的图标/视觉，不能只是看起来像文字。

### R10 — 衰减折线图

- 当前相机高度与衰减折线图破碎、无法使用。
- 需要重做，至少达到旧 SR 的可用水平。
- 建议纳入对应功能块，并随功能块一起滚动/导航。

### R11 — 组合式功能块与 UiKit 容器化

- 控件按功能块组合；功能块可组合成更大的功能块。
- 示例：Action Scope + Mood Tuning = 完整 Tuning Editor。
- XML 上应能体现结构层次，而不是扁平 `<Widget>` 列表。
- 当前 UiKit `LayoutManifest` 只支持扁平根节点，需要新增容器能力（如 `Block` / `Section` / `Column`）并让 Measure/Draw/交互递归处理子节点。

## 建议实施顺序

1. **P0**：重做衰减折线图。
2. **P1**：功能块独立滚动 + 标题导航 + 包过滤器归位。
3. **P1**：帮助系统收敛到右侧面板（移除/弱化内联帮助）。
4. **P1**：Tuning Editor 下拉 + Mood 复合控件。
5. **P2**：UiKit 容器化，落地组合式功能块 XML 结构。

> 具体实施前仍需维护者确认优先级与方案。
