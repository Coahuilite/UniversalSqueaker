# v0.6.0-rc1 — release-candidate scope / 候选范围

## English

RimWorld **1.6 only**. This is a prerelease, not Latest. The numeric product/About version is 0.6.0; rc1 identifies the tag and download. The ea610fa/FL833c14f4 baseline received overall internal-trial acceptance. No itemized fifteen-action, IME, native Config or screen matrix was supplied; those remain scoped known limits, not fabricated passes.

- Ordinary Release responses initialize without Dev mode. One platform-free Core and synchronous owner cover all fifteen declared actions, precise subjects and explicit event consumers.
- Accepted Select uses 0.3 real seconds; Draft/Undraft each 0.6. Simulation uses game ticks. Explicit accepted-operation facts prevent stale/repeated-root replay; no silent legacy clock fallback or reinterpretation of old units.
- Voice management has direct secondary tools, contextual bottom help, independent complete category/source/query paging, explicit fallback-table creation and three data palettes. At a logical 1024 × 768 resolution, the window opens centred at 864 × 640. Vanilla Options has a packaged microphone entry.
- US ships no voices and no prerequisite DLLs. Install Harmony and the **actual paired FerriteLib release named in the release identity**, both before US. A local explicit carrier candidate is not a published RC2 asset.

### Upgrade and recovery

Back up your configuration yourself before upgrading. The 0.6 declaration/configuration/API boundary is breaking: update author examples and fields to the [current contract](../response-opportunities-0.6-zh.md). Old timing fields are rejected, not converted to seconds or executed. Unchanged pack/audio/appearance data is not cleared. On the exact selected domain, explicitly choose inheritance or rebind an updated source, including the same source ID; a failed atomic commit retains the original data. General malformed XML is not auto-repaired. A rollback needs the corresponding older configuration, not an attempt to run new fields on the old DLL.

Native sound still requires applicable supply, race admission, qualification, player enablement and normal protection/resource readiness. Table-only new race admission requires a full restart. Uninstall remains save-safe: US writes no persistent save data; external settings/profiles remain in Config.
